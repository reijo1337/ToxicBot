# Приёмка событий реакций и откат

Этот документ сохраняется после архивации OpenSpec change. Ручные результаты обновляются
здесь; закрытие реализации не означает выполнения проверки на живом стенде.

## REACT-010: проверка доставки Telegram

Статус: **не выполнена**. В этой сессии не предоставлена тестовая группа с ботом-администратором.
Автотест HTTP-конверта проверяет обработку доставленных событий, но не выдачу прав и доставку
на стороне Telegram.

1. Развернуть проверяемую версию в отдельной тестовой группе. Назначить бота администратором.
   Убедиться, что запущен один экземпляр, получающий обновления этого бота.
2. Написать сообщение обычным участником, получить сообщение бота. На каждом поставить 👍,
   заменить на 👎, затем снять. После каждого действия дождаться обработки.
3. Проверить в истории события с правильным автором действия, ID цели и временем Telegram:
   постановка, одно событие замены (снятие 👍 и добавление 👎), снятие 👎. У реакции на бота
   автор цели — бот; его текст не появляется в материале пинга через событие реакции.
4. Выполнить анонимное действие от имени чата, если группа поддерживает его. Убедиться, что
   `actor_chat` и агрегированные счётчики не записываются как персональные события.
5. Проверить, что сами реакции не вызывают сообщения бота и не регистрируют нового кандидата
   теггера. Отправить обычные текст, фото и событие вступления: прежняя доставка работает.
6. Для проверки без административных прав использовать отдельный этап: отсутствие доставки
   не считать доказательством отсутствия реакций. После проверки вернуть нужные права.

Результат: дата / версия / выполненные пункты / наблюдения — **ожидает живого стенда**.
В отчёт не включать токены, полные апдейты, содержимое переписки и персональные ID.

## Резервная копия и откат перед развёртыванием

Статус: **не выполнены на целевом сервере**. Развёртывание не входило в текущий запуск.
Рабочая SQLite находится на сервере в `/srv/ToxicBot/db/sas_sqlite.db`
(в контейнере `/toxicdb/sas_sqlite.db`, см. `deploy/deploy.yaml`).

1. Зафиксировать текущую версию образа и остановить бот, исключив параллельные записи.
2. Сохранить согласованную совместимую копию SQLite до первого запуска новой версии.
   При копировании файлов учесть WAL/SHM; предпочтительна штатная согласованная резервная
   копия SQLite. Проверить её целостность и пробное чтение истории старой версией на изолированной
   копии, не подключая её к Telegram.
3. Сохранить путь копии, версию, дату и результат проверки вне публичного отчёта.
4. При откате остановить новую версию, отдельно сохранить текущую SQLite, восстановить
   совместимую копию из пункта 2 и только затем запустить старый образ.
5. Проверить чтение истории и работу обычных сообщений. Учесть потерю всех записей после
   резервной копии: это касается всей SQLite, а не только истории.

Старую версию нельзя запускать непосредственно на смешанном окне с реакциями: старый
gob-декодер игнорирует неизвестное поле, но оставляет запись события пустой репликой.
Копия новой SQLite перед откатом не заменяет совместимую копию до обновления. Откат
с сохранением более новых сообщений потребует отдельного офлайн-преобразования вне этой задачи.

Результат: версия / подтверждение копии и пробного восстановления — **ожидает развёртывания**.
