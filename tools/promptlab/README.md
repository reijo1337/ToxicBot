# promptlab

Offline-стенд: прогоняет варианты системного промпта и разные модели по реальным
ситуациям из прода и складывает ответы рядом в markdown, чтобы сравнивать глазами.

Путь генерации тот же, что в бою: харнесс собирает настоящий `message.Generator`,
так что envelope `<msg from= now=>`, сортировка истории, блок `<examples>` и
`sanitize` совпадают с продом. Для tag-кейсов вызывается настоящий
`GetMessageTextForTag` с `aiChance=1`: разделение собственных сообщений и фона,
исключение бота и правила таймера выполняет сам генератор. Стенд может подменять
базовый промпт и модель.

## Данные

Каталог `data/` в gitignore: там переписка чатов и отчёты.

| Файл | Откуда |
|---|---|
| `data/sas_sqlite.db` | копия прод-базы: `make promptlab-fetch` |
| `data/cases.json` | `make promptlab-extract` |
| `data/examples.txt` | фразы из Google Sheets (вкладка с сообщениями), по одной на строку |
| `data/report.md` | результат `make promptlab-run` |

Кейс — окно истории чата, в конце которого бот в проде ответил. Триггер — последняя
реплика человека, ответ из прода лежит в колонке «В проде». Для фото-кейсов
повторяется путь `on_photo`: ответы бота выкидываются из окна, добавляется
анти-шаблонный steering.

## Промпты

`prompts/*.txt` — варианты базовой части системного промпта (всё до `<examples>`).
Имя файла — имя варианта в отчёте. `baseline` зарезервирован за промптом из кода и
гоняется всегда, если не передать `--no-baseline`.

Стартовый вариант: `go run ./tools/promptlab dump-prompt --out tools/promptlab/prompts/v2.txt`.

## Модели

`promptlab.yaml` — список OpenAI-совместимых точек входа. Ключи только через
переменные окружения. Поля `extra_body` уходят в тело запроса как есть
(`thinking: {type: disabled}` для DeepSeek).

## Запуск

Ключи — в окружении или в `data/.env` (формат `KEY=value`, каталог в gitignore):

```bash
make promptlab-fetch host=95.81.112.114   # копия базы с VDS
make promptlab-extract                    # data/cases.json
make promptlab-run                        # data/report.md, все варианты × все модели
```

Точечно:

```bash
make promptlab-run args="--models deepseek-flash --variants baseline,v2 --limit 10 --kind text"
```


## Проверка авторства пингов

Tag-кейсы задаются явно: `kind: "tag"`, объект `target` с положительным `user_id`,
`author` и `nickname`; в пользовательских записях истории указывается `sender_id`.
Значение `0` или отсутствие поля означает неизвестного отправителя. Совпадение
подписи с адресатом не восстанавливает его ID. Text/photo JSON прежнего формата
без этих полей продолжает читаться. Извлечение истории сохраняет `sender_id`, но
не восстанавливает пинги из `response_log`: там нет полного окна и текста ответа.

В таймерном пути адресат выбирается из пересечения реестра участников и уникальных
положительных `SenderID` неботов одного снимка истории. Этот же снимок получает
генератор. При пустом пересечении попытка пропускается до проверки членства,
генерации и отправки, а следующая задача перепланируется; реестр сохраняется.
Правило действует и при `ai_chance=0`. Совпадение подписи и старые записи без ID
не дают допуска. Поэтому после обновления с legacy-истории пинги возобновятся
по мере появления новых достоверных авторов, без угадывания ID или очистки истории.
При прямом вызове `GetMessageTextForTag` без собственной достоверной записи
адресата генератор использует список и не вызывает AI.

Шесть AI-кейсов в `testdata/tag-attribution.json` полностью синтетические: ID,
подписи, ссылки, реплики и прежние ответы бота придуманы для этой проверки.
В каждом кейсе есть непустая собственная реплика адресата с достоверным ID.
Прежние ответы бота намеренно включены во вход, чтобы настоящий tag-путь исключал
их самостоятельно. `--steering-file` и `--bot-history` применяются только к
прежним режимам text/photo и не меняют tag-запрос.

| ID кейса | Что проверять в ответе |
|---|---|
| `tag-phone-discussion-author` | Адресат `91002` — автор ссылки и вопроса о телефоне; пинг может опираться на его слова, но вопрос о чужом телефоне не доказывает владение |
| `tag-own-before-foreign-threat` | Своя полка допустима; чужая более свежая угроза не принадлежит адресату |
| `tag-identical-authors` | Одинаковые подписи не передают адресату чужую покупку телефона |
| `tag-renamed-account` | Старые и новые собственные сообщения связаны по ID; чужой старый username не передаёт покупку адресату |
| `tag-legacy-with-known-author` | Новая собственная реплика о сборке лампы допустима; старые записи без ID о телефоне остаются фоном даже при совпадении подписи |
| `tag-own-question-about-other-phone` | Собственный вопрос адресата о чужом телефоне не доказывает владения им |

Отрицательная матрица хранится отдельно в `testdata/tag-attribution-negative.json`.
Это точные прежние синтетические входы из `data/tag-attribution/run-01/cases.json`:
авторство в них не исправлялось задним числом.

| ID отрицательного кейса | Ожидаемый результат |
|---|---|
| `tag-absent-phone` | Адресата `91001` нет среди достоверных авторов: таймер не выбирает его, прямой генератор использует список без AI |
| `tag-legacy-unknown-sender` | Собственные записи известны только по подписи с `sender_id=0`: того же допуска нет, прямой генератор использует список без AI |

Эти два случая проверяются тестами через настоящие `Load`, `DomainHistory` и
генератор без обращения к внешнему API. Они не входят в шесть AI-кейсов и не
засчитываются в 60 содержательных ответов. Пустая/только бот история и авторы вне
реестра дополнительно проверяются unit-тестами таймерного пути.

Первый `run-01` отклонён: сохранены все 60 результатов и восемь ручных оценок
(одна `pass`, семь провалов). Следующий прогон хранится отдельно в `run-02`;
прежние результаты и оценки не перезаписываются.

Прогон шести AI-кейсов по текущей продовой конфигурации и фиксированному пулу примеров:

```bash
mkdir -p tools/promptlab/data/tag-attribution/run-02
# Сначала положить фиксированный пул в data/tag-attribution/examples.txt.
# Ключ DEEPSEEK_API_KEY уже должен быть в окружении (либо использовать make).
go run ./tools/promptlab run \
  --cases tools/promptlab/testdata/tag-attribution.json \
  --examples tools/promptlab/data/tag-attribution/examples.txt \
  --config tools/promptlab/promptlab.yaml \
  --kind tag --models deepseek-flash --variants baseline --repetitions 10 \
  --out tools/promptlab/data/tag-attribution/run-02/report.md \
  --jsonl tools/promptlab/data/tag-attribution/run-02/results.jsonl
```

`--repetitions` по умолчанию равен `1`; разрешены только положительные числа.
Каждый повтор получает свой `repetition` в JSONL и отдельную запись в ячейке
markdown-отчёта, включая ошибки и fallback. Повторы не усредняются и не затираются.
В tag-отчёте показывается адресат: новая входящая реплика для таймера не выдумывается.
Зафиксируйте рядом версию кода, команду, конфигурацию модели, список кейсов и
неизменный пул примеров, чтобы смысл результатов можно было проверить повторно.

Каждому ответу человек ставит `pass`, `attribution_error` или `other_failure`
с короткой причиной в отдельном `data/tag-attribution/run-02/review.jsonl`, например:

```json
{"case_id":"tag-phone-discussion-author","variant":"baseline","model":"deepseek-flash","repetition":1,"verdict":"pass","reason":"Пинг опирается на вопрос адресата; владение чужим телефоном ему не приписано."}
```

Ошибка определяется смыслом: упоминание телефона или местоимения само по себе
не означает ошибку. Для приёмки нужны 60 содержательных AI-ответов без ошибок
авторства и иных содержательных провалов. API-ошибка или fallback сохраняется,
но успехом не считается; технический повтор сохраняйте в новых файлах и связывайте
с исходным результатом. Содержательный провал повтором не стирать: он требует
пересмотра change до следующей правки кода. Сырые результаты и ручная разметка
остаются в gitignored `data/`.
