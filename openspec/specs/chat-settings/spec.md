# chat-settings

## Purpose

Как чат настраивает бота под себя: какие параметры переопределяются, как команда `/settings` их
показывает и меняет, и как изменение доезжает до обработчиков.

## Requirements

### Requirement: Настройки чата переопределяют глобальные значения
Незаданные параметры чата SHALL брать значение из глобальных настроек бота.

#### Scenario: [SET-001] чат ничего не переопределял
- GIVEN для чата нет сохранённых настроек
- WHEN обработчик запрашивает настройки
- THEN возвращаются глобальные значения по умолчанию

#### Scenario: [SET-002] переопределена часть параметров
- GIVEN для чата задан только один параметр
- WHEN обработчик запрашивает настройки
- THEN этот параметр берётся из настроек чата, остальные — из умолчаний

#### Scenario: [SET-003] настройки кешируются на минуту
- GIVEN настройки чата уже читались
- WHEN обработчик запрашивает их снова в пределах минуты
- THEN обращение к хранилищу не повторяется

#### Scenario: [SET-004] изменение сбрасывает кеш
- GIVEN настройки чата закешированы
- WHEN настройки изменены или сброшены
- THEN кеш чата очищается, следующее чтение идёт в хранилище

### Requirement: Команда показывает и меняет настройки
`/settings` SHALL показывать текущие значения рядом с умолчаниями, менять одно значение и
сбрасывать все.

#### Scenario: [SET-005] показ настроек
- GIVEN команда вызвана без аргументов
- WHEN бот отвечает
- THEN выводятся все параметры с текущими значениями и значениями по умолчанию

#### Scenario: [SET-006] изменение параметра
- GIVEN команда вызвана с именем параметра и значением
- WHEN значение корректно
- THEN параметр сохраняется для этого чата

#### Scenario: [SET-007] сброс настроек
- GIVEN команда вызвана со словом `reset`
- WHEN бот обрабатывает команду
- THEN переопределения чата удаляются, бот возвращается к умолчаниям

#### Scenario: [SET-008] неверное значение отклоняется
- GIVEN значение не разбирается или выходит за допустимые границы
- WHEN бот обрабатывает команду
- THEN настройка не меняется, в ответ приходит объяснение с примером

#### Scenario: [SET-009] неизвестный параметр или лишние аргументы
- GIVEN имя параметра не поддерживается или аргументов больше трёх
- WHEN бот обрабатывает команду
- THEN выводится подсказка по использованию

#### Scenario: [SET-010] команда в личке
- GIVEN команда вызвана в личном чате с ботом
- WHEN бот обрабатывает её
- THEN он отвечает отказом и настройки не показывает

### Requirement: Настройки переживают перезапуск
Переопределения чата SHALL храниться в базе и читаться после рестарта.

#### Scenario: [SET-011] сохранение и чтение
- GIVEN настройки чата сохранены
- WHEN бот перезапускается и читает их
- THEN возвращаются сохранённые значения

#### Scenario: [SET-012] настройки изолированы по чатам
- GIVEN настройки заданы в двух чатах
- WHEN читаются настройки одного
- THEN значения другого на него не влияют

## Наблюдения

- Настраиваемые параметры: `threshold_count`, `threshold_time`, `cooldown`, `sticker_chance`,
  `voice_chance`, `ai_chance`, `photo_chance`.
- **Прав доступа команда не проверяет.** `AGENTS.md` описывает `/settings` как доступную только
  администраторам групповых чатов, но в коде нет ни одной проверки роли: настройки чата может
  поменять любой участник группы. Единственное ограничение — отказ в личных сообщениях.
  Расхождение реальное: либо проверку надо добавить, либо документацию поправить. До решения это
  наблюдение, а не контракт.
- Сообщения об ошибках выдержаны в тоне бота и содержат пример корректного значения.
- Кеш живёт минуту, поэтому изменение вступает в силу не мгновенно.
