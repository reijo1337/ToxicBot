# llm-clients

## Purpose

Как бот разговаривает с языковыми моделями: что отправляет, как понимает ответ и что считает
непригодным результатом. DeepSeek — основной клиент, GigaChat — второй.

Решение о том, звать ли модель вообще, принимает [message-generation]; здесь только сам разговор.

## Requirements

### Requirement: Запрос к модели содержит роли и параметры генерации
Клиент SHALL передавать диалог с ролями и ограничивать генерацию параметрами из конфигурации.

#### Scenario: [LLM-001] имя автора идёт только с репликами участников
- GIVEN диалог содержит системную инструкцию и реплики с именами
- WHEN формируется запрос
- THEN имя проставляется репликам участников и ассистента, но не системной инструкции

#### Scenario: [LLM-002] пустой запрос отклоняется
- GIVEN список сообщений пуст
- WHEN вызывается генерация
- THEN клиент возвращает ошибку, не обращаясь к API

#### Scenario: [LLM-003] лимит длины и температура уходят в запрос
- GIVEN клиент настроен значениями `max_tokens` и `temperature`
- WHEN формируется запрос
- THEN эти параметры присутствуют в теле запроса

#### Scenario: [LLM-004] режим размышления выключен
- GIVEN модель поддерживает режим размышления
- WHEN формируется запрос
- THEN режим явно выключен, чтобы reasoning-токены не съедали бюджет ответа

### Requirement: Непригодный ответ отличается от пригодного
Клиент SHALL возвращать ошибку, если модель не довела ответ до конца, чтобы вызывающий откатился
на список, а не отправил в чат обрывок.

#### Scenario: [LLM-005] ответ обрезан по длине
- GIVEN модель завершила генерацию по причине `length`
- WHEN клиент разбирает ответ
- THEN возвращается ошибка обрезанного ответа, а не частичный текст

#### Scenario: [LLM-006] ответ остановлен фильтром
- GIVEN модель завершила генерацию по причине `content_filter`
- WHEN клиент разбирает ответ
- THEN возвращается ошибка обрезанного ответа

#### Scenario: [LLM-007] нормально завершённый ответ отдаётся как есть
- GIVEN модель завершила генерацию по причине `stop`
- WHEN клиент разбирает ответ
- THEN возвращается текст ответа

#### Scenario: [LLM-008] ошибка транспорта заворачивается
- GIVEN API отвечает ошибкой HTTP
- WHEN клиент выполняет запрос
- THEN возвращается ошибка с контекстом вызова

### Requirement: Второй провайдер ведёт себя так же
GigaChat SHALL отдавать текст при успехе и ошибку при любом непригодном ответе, а токен доступа
переиспользовать до истечения.

#### Scenario: [LLM-009] успешная генерация
- GIVEN API отвечает корректным результатом
- WHEN клиент запрашивает генерацию
- THEN возвращается текст ответа

#### Scenario: [LLM-010] ошибка транспорта
- GIVEN API отвечает ошибкой HTTP
- WHEN клиент запрашивает генерацию
- THEN возвращается ошибка

#### Scenario: [LLM-011] ответ без содержимого
- GIVEN API вернул пустой список вариантов или пустой текст
- WHEN клиент разбирает ответ
- THEN возвращается ошибка, пустая строка в чат не уходит

#### Scenario: [LLM-012] токен доступа переиспользуется
- GIVEN токен уже получен и ещё не истёк
- WHEN выполняется следующий запрос
- THEN повторный поход за токеном не выполняется

#### Scenario: [LLM-013] без ключа клиент не создаётся
- GIVEN ключ авторизации не задан
- WHEN клиент создаётся
- THEN создание завершается ошибкой

#### Scenario: [LLM-014] ошибка загрузки файла
- GIVEN загрузка файла в API завершается неуспешно
- WHEN клиент выполняет загрузку
- THEN возвращается ошибка

### Requirement: Обращения к модели наблюдаемы
Каждый вызов модели SHALL порождать спан с параметрами и содержимым обмена.

#### Scenario: [LLM-015] вызов модели виден в трейсе
- GIVEN трейсинг включён
- WHEN бот обращается к модели
- THEN создаётся `gen_ai`-спан с моделью, длинами и, если разрешено, текстом запроса и ответа

## Наблюдения

- DeepSeek построен на официальном SDK OpenAI через переопределённый `BaseURL`, поэтому запрос
  уходит на `<base>/chat/completions`.
- Значения по умолчанию: `max_tokens` 500, `temperature` 1.1, таймаут 30 секунд, три повтора.
  Запас по токенам взят над целью «300 символов» с учётом кириллической токенизации и обёртки,
  которую модель иногда добавляет сверху.
- Захват текста в спанах управляется настройкой трейсинга; при её выключении в спанах остаются
  только длины.
