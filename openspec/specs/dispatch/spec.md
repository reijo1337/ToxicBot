# dispatch

## Purpose

Как одно событие Telegram раздаётся обработчикам: кто запускается, что происходит с ошибками и как
это выглядит в трейсах.

## Requirements

### Requirement: Обработчики одного события работают параллельно
Все обработчики, подписанные на событие, SHALL запускаться одновременно и не ждать друг друга.

#### Scenario: [DISP-001] событие раздаётся всем обработчикам
- GIVEN на событие подписано несколько обработчиков
- WHEN приходит обновление
- THEN каждый обработчик получает событие, и они выполняются параллельно

#### Scenario: [DISP-002] падение одного не отменяет остальных
- GIVEN один из обработчиков возвращает ошибку
- WHEN обновление обрабатывается
- THEN остальные обработчики доводят работу до конца

#### Scenario: [DISP-003] ошибки собираются вместе
- GIVEN несколько обработчиков вернули ошибки
- WHEN обработка завершается
- THEN наверх уходит одна ошибка, объединяющая все, с указанием события

### Requirement: Обработка обновления наблюдаема
Каждое обновление SHALL порождать корневой спан, от которого ветвятся спаны обработчиков.

#### Scenario: [DISP-004] корневой спан назван по событию
- GIVEN трейсинг включён
- WHEN приходит обновление
- THEN создаётся корневой спан с именем события и атрибутами обновления

#### Scenario: [DISP-005] ошибка помечает спан
- GIVEN обработчик вернул ошибку
- WHEN обработка завершается
- THEN корневой спан получает статус ошибки и запись о ней

## Наблюдения

- Корневой контекст кладётся в контекст telebot, чтобы обработчики могли подцепить к нему свои
  спаны, не прокидывая его аргументом.
- Периодический теггер работает вне этого пути: у него собственный корневой спан с признаком
  запуска по таймеру.
