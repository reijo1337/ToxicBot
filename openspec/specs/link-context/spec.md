# link-context Specification

## Purpose
Дополнять отправленную ссылку сведениями OpenGraph и машинным описанием превью, чтобы бот понимал
тему материала и сохранял её для последующего контекста разговора.

## Requirements

### Requirement: Обрабатывается только первая ссылка сообщения
Бот SHALL выбирать только первую HTTP(S)-ссылку в порядке появления в тексте или подписи
записываемого сообщения, включая скрытые ссылки Telegram. Остальные ссылки MUST NOT загружаться,
в том числе при неудаче первой. Факт отображения превью Telegram MUST NOT влиять на обогащение.
Для скрытой ссылки бот SHALL сохранять её видимую подпись вместе с адресом, отдельно от данных сайта.

#### Scenario: [LINK-001] первая ссылка бывает обычной или скрытой
- GIVEN первая ссылка сообщения представлена видимым URL либо скрытой ссылкой Telegram
- WHEN бот обогащает сообщение
- THEN выбирается адрес первой ссылки независимо от отображаемого текста
- AND Unicode и emoji перед ссылкой не смещают адрес
- AND у скрытой ссылки сохраняется подпись из её диапазона в тексте или подписи сообщения
- AND для обычного видимого URL дополнительная подпись не создаётся
- AND видимый URL без схемы, размеченный Telegram как ссылка, получает схему `http://`

#### Scenario: [LINK-002] остальные ссылки не загружаются
- GIVEN сообщение содержит несколько HTTP(S)-ссылок
- WHEN выполняется обогащение
- THEN обрабатывается только первая ссылка по порядку в сообщении
- AND исходный текст остальных ссылок остаётся в сообщении

#### Scenario: [LINK-003] отсутствующие и некорректные ссылки
- GIVEN сообщение не содержит пригодных HTTP(S)-ссылок либо содержит некорректные границы ссылки
- WHEN выполняется обогащение
- THEN непригодные ссылки пропускаются без ошибки и сетевых запросов к ним
- AND исходное сообщение остаётся доступно

#### Scenario: [LINK-017] неудача первой ссылки не переключает на следующую
- GIVEN сообщение содержит несколько ссылок, а первая недоступна, запрещена или не содержит OpenGraph
- WHEN выполняется обогащение
- THEN следующие ссылки не загружаются и не описываются
- AND остаётся исходное сообщение и доступные поля только первой ссылки

#### Scenario: [LINK-018] наличие карточки Telegram не учитывается
- GIVEN у сообщения со ссылкой есть либо отсутствует видимое превью Telegram, в том числе оно отключено
- WHEN бот выбирает ссылку для обогащения
- THEN обрабатывается первая HTTP(S)-ссылка по одинаковым правилам, независимо от карточки

### Requirement: Поля OpenGraph независимы друг от друга
Бот SHALL извлекать первый непустой заголовок, описание и адрес превью OpenGraph из доступного
HTML страницы. Отсутствующее поле MUST NOT приводить к потере остальных или выдумываться.
Исходный URL SHALL оставаться связан с полученными сведениями.

#### Scenario: [LINK-004] заголовок и описание страницы
- GIVEN страница содержит заголовок и описание OpenGraph
- WHEN бот загружает её по ссылке
- THEN оба поля доступны в контексте ссылки вместе с исходным URL
- AND HTML entities декодированы в обычный текст
- AND ведущий UTF-8 BOM не препятствует чтению OpenGraph

#### Scenario: [LINK-005] неполный набор полей
- GIVEN страница содержит только заголовок, только описание либо только превью OpenGraph
- WHEN выполняется обогащение
- THEN доступные поля используются независимо от отсутствующих
- AND отсутствие остальных обязательных свойств OpenGraph не отменяет результат

#### Scenario: [LINK-006] OpenGraph отсутствует
- GIVEN страница не содержит поддерживаемых полей OpenGraph
- WHEN выполняется обогащение
- THEN сообщение остаётся с исходным текстом, без пустого блока ссылки или выдуманного описания

#### Scenario: [LINK-007] редирект и относительная картинка
- GIVEN страница перенаправляет на публичный адрес и содержит относительный адрес превью
- WHEN бот определяет адрес картинки
- THEN адрес разрешается относительно конечной страницы либо её корректного базового URL
- AND канонический URL из метаданных не подменяет исходную ссылку и не запускает дополнительную загрузку

### Requirement: Превью получает самостоятельное машинное описание
Бот SHALL описывать первое непустое превью OpenGraph, если оно доступно в поддерживаемом формате
и укладывается в пределы загрузки. Запрос SHALL учитывать, что это иллюстрация ссылки, и требовать
краткого описания видимого содержания, темы и существенного текста. Он MUST NOT требовать выдумывать
содержание страницы или связь людей на картинке с отправителем.

#### Scenario: [LINK-008] превью описано
- GIVEN страница содержит доступное JPEG- или PNG-превью допустимого размера
- WHEN обогащение завершается успешно
- THEN к ссылке добавляется отдельное описание изображения на русском
- AND описание основывается на картинке, без подмешивания заголовка и описания страницы в запрос vision

#### Scenario: [LINK-009] ошибка картинки не теряет текст страницы
- GIVEN заголовок или описание страницы получены, но картинка недоступна, неподдерживаема или её описание не удалось
- WHEN завершается обработка ссылки
- THEN текстовые поля сохраняются, а описание превью отсутствует
- AND обработка исходного сообщения продолжается

#### Scenario: [LINK-010] текст картинки не становится инструкцией
- GIVEN на превью есть надпись, в том числе инструкция для модели
- WHEN формируется запрос описания
- THEN правила требуют передавать надпись как цитируемые данные, не исполнять её и не обращаться к читателю
- AND для превью используется отдельная инструкция, сохраняющая прежнее поведение обычных фотографий

### Requirement: Внешние загрузки ограничены
Бот SHALL загружать страницы и картинки только из публичного HTTP(S)-интернета, с ограничениями
времени, объёма, редиректов и параллелизма. Ограничения SHALL действовать и для адресов, полученных
через DNS или редирект. Обогащение сообщения SHALL завершаться не позднее 20 секунд и возвращать
уже полученные поля; ошибка MUST NOT терять исходное сообщение или отменять обычную реакцию.

#### Scenario: [LINK-011] внутренний адрес не загружается
- GIVEN исходная ссылка, редирект, DNS-ответ или адрес превью указывает на непубличный или специальный адрес, включая metadata, CGNAT и IPv6-варианты
- WHEN бот пытается загрузить ресурс
- THEN соединение с запрещённым адресом не устанавливается
- AND повторное разрешение DNS не позволяет обойти проверку фактического адреса соединения

#### Scenario: [LINK-012] превышены пределы ресурса
- GIVEN ответ слишком велик, не подходит по типу, содержит чрезмерную картинку либо цепочку редиректов
- WHEN бот обрабатывает ресурс
- THEN дальнейшая загрузка или обработка прекращается в пределах заданных ограничений
- AND ранее полученные допустимые поля остаются доступны

#### Scenario: [LINK-026] сжатый ответ не распаковывается
- GIVEN сервер вернул сжатый ответ вопреки запросу несжатого содержимого
- WHEN загрузчик проверяет ответ
- THEN ресурс пропускается без распаковки и дальнейшей обработки
- AND ранее полученные допустимые поля остаются доступны

#### Scenario: [LINK-013] истёк бюджет обогащения
- GIVEN загрузка или описание превью не успевает завершиться за общий бюджет
- WHEN бюджет исчерпан
- THEN бот продолжает обработку с уже полученными полями и исходным текстом
- AND не ждёт завершения недоступного ресурса сверх бюджета сообщения

### Requirement: Запросы к сайтам не получают полномочий бота
Загрузчик SHALL делать только анонимные GET без тела и без передачи ключей, cookies, заголовков
авторизации, Referer или сведений чата. Использование proxy из окружения MUST NOT обходить проверку
назначения. Каждый редирект SHALL повторно проходить проверки, переход с HTTPS на HTTP запрещён.
Для HTTPS SHALL проверяться сертификат и имя сервера. HTML и выход модели MUST NOT запускать
дополнительные действия или запросы кроме выбранной страницы и её первого превью.

#### Scenario: [LINK-020] внешний запрос анонимен
- GIVEN процесс бота имеет API-ключи, а сайт присылает cookies или требует авторизацию
- WHEN загружаются страница, редирект либо картинка
- THEN получатель не получает ключей, Cookie, Authorization, Referer, идентификаторов чата или trace-заголовков
- AND cookies ответа не становятся полномочиями последующих запросов
- AND настройка proxy в окружении не меняет защищённый маршрут загрузки

#### Scenario: [LINK-021] редирект не переносит полномочия и проходит проверки
- GIVEN публичная страница перенаправляет на другой адрес
- WHEN обрабатывается Location
- THEN новый адрес проверяется до соединения и получает только фиксированные анонимные заголовки
- AND запрещённые адрес, схема, порт, downgrade HTTPS либо превышение трёх редиректов прекращают цепочку

#### Scenario: [LINK-022] контент не создаёт дополнительные сетевые действия
- GIVEN HTML, метаданные или ответ vision содержат скрипт, форму, refresh либо указание перейти по дополнительной ссылке
- WHEN бот обрабатывает страницу и описание превью
- THEN перечисленные инструкции не исполняются, модели не предоставляются инструменты загрузки
- AND допустимы только GET выбранной первой страницы и первого превью с проверенными редиректами

#### Scenario: [LINK-025] ошибка TLS не обходится
- GIVEN HTTPS-ресурс имеет недоверенный сертификат или несовпадающее имя сервера
- WHEN выполняется загрузка
- THEN запрос прекращается без отключения проверки TLS, перехода на HTTP или другого клиента
- AND обработка исходного сообщения продолжается с ранее доступными полями

#### Scenario: [LINK-027] ошибка запроса не запускает повтор
- GIVEN выбранный ресурс отвечает 429, 5xx либо соединение завершается ошибкой
- WHEN завершается эта попытка
- THEN в рамках данного обогащения запрос не повторяется и не заменяется HEAD
- AND доступные поля возвращаются без ожидания Retry-After или нового backoff

### Requirement: Частота загрузок и диагностика ограничены
Помимо пределов одного ресурса, бот SHALL ограничивать частоту и число одновременно начатых
обогащений, HTTP- и vision-запросов на процесс, чат и получателя. Перегрузка MUST NOT создавать
неограниченную очередь. Новая диагностика загрузчика MUST NOT раскрывать полный URL или содержимое
страницы, ответа либо сообщения.

#### Scenario: [LINK-023] поток уникальных ссылок не создаёт неограниченную нагрузку
- GIVEN новые ссылки исчерпали лимит частоты или слоты обогащения
- WHEN поступает очередное сообщение со ссылкой
- THEN новая загрузка не запускается и не ставится в неограниченную очередь
- AND исходное сообщение обрабатывается с доступными полями
- AND cache hit не расходует квоты внешних запросов, а картинки и редиректы расходуют их

#### Scenario: [LINK-024] ошибка с токеном в URL не раскрывается диагностикой
- GIVEN URL, Location или текст сетевой ошибки содержит секретный query или path
- WHEN загрузчик фиксирует отказ в новом логе или спане
- THEN полные URL, path/query и необработанный текст ошибки в диагностику не попадают
- AND сохраняются стадия, фиксированная причина, hostname и безопасные числовые параметры

### Requirement: Повторные ссылки используют ограниченный кеш
Бот SHALL временно переиспользовать результаты одной ссылки и объединять её одновременные загрузки.
Кеш SHALL иметь ограниченный размер и срок хранения; изменение кеша MUST NOT менять ранее сохранённую
историю сообщения.

#### Scenario: [LINK-014] ссылка повторилась
- GIVEN для ссылки есть актуальный результат, включая описание превью
- WHEN она приходит в другом сообщении
- THEN результат используется без повторной загрузки страницы и вызова vision
- AND регистр схемы и hostname, стандартный порт, конечная точка hostname, Unicode/punycode и fragment не разделяют кеш
- AND разные исходные query не объединяются в одну ссылку

#### Scenario: [LINK-015] одновременное обращение и отмена
- GIVEN два сообщения одновременно обрабатывают одну ссылку
- WHEN одно из сообщений перестаёт ждать результат
- THEN общая загрузка не дублируется и может завершиться для второго сообщения
- AND каждое сообщение соблюдает собственный предел ожидания

#### Scenario: [LINK-016] кеш истёк или заполнен
- GIVEN срок результата истёк либо кеш достиг максимального размера
- WHEN появляются новые обращения
- THEN устаревшие результаты обновляются, старые ключи вытесняются, размер кеша остаётся ограниченным
- AND сохранённые сообщения не переписываются и не обогащаются повторно при чтении

#### Scenario: [LINK-019] подпись скрытой ссылки принадлежит своему сообщению
- GIVEN два сообщения содержат один URL с разными видимыми подписями скрытой ссылки
- WHEN сведения страницы переиспользуются из кеша либо общей одновременной загрузки
- THEN каждое сообщение получает собственную подпись ссылки и исходное написание URL
- AND подпись из одного сообщения не подменяет подпись другого
